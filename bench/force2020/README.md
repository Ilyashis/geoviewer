# Стенд для проверки автокорреляции — FORCE 2020

Автокорреляция разбивок (`src/wells/correlate.ts`) написана, но не подключена
к интерфейсу: на единственных доступных реальных данных (`private-data/`,
конфиденциальные) проверка дала медиану ошибки 64.7 м на 20 сравнениях —
слишком мало и слишком неблагоприятная выборка (скважины без общего интервала
записи, разные приборы), чтобы вынести приговор методу. Подробности —
[docs/product/correlation.md](../../docs/product/correlation.md).

Этот стенд — открытые данные взамен: набор больше, скважины можно отобрать по
сближенности, а разбивки — от официального регулятора (NPD), а не подогнаны
под тест.

## Источник и лицензия

**FORCE 2020 Lithology dataset**, куратор — Норвежский нефтяной директорат
(NPD) / FORCE. Опубликовано на Zenodo:
<https://zenodo.org/records/4351156>, лицензия **CC BY 4.0** (коммерческое
использование разрешено при указании авторства).

Используемые файлы (не входят в репозиторий — см. «Как собрать» ниже):

| Файл | Размер | Содержимое |
|---|---|---|
| `LAS_files_Force_2020_all_wells_train_test_blind_hidden_final.zip` | ~170 МБ | LAS-каротаж по 118 скважинам |
| `NPD_Lithostratigraphy_member_formations_all_wells.xlsx` | ~165 КБ | 1914 разбивок (Well, Surface, X, Y, Z, MD) от NPD |

**Атрибуция**: данные и разбивки — Norwegian Petroleum Directorate (NPD),
через конкурс FORCE 2020, CC BY 4.0, Zenodo DOI 10.5281/zenodo.4351156.

## Почему именно этот набор

- **Разбивки от регулятора**, не размечены для теста — как разбивки геолога
  в `private-data`, только их 1914 против 20.
- **118 скважин на весь шельф** (150×450 км) — то есть *не* готовый плотный
  кластер. Первый шаг стенда — найти скопления, где корреляция вообще имеет
  шанс: та же ошибка, что чуть не привела к неверному выводу на
  `private-data` (см. correlation.md), стенд обязан не повторить.
- **LAS-каротаж** — заодно нагружает собственный парсер LAS на 118 файлах
  незнакомого происхождения.

## Как собрать локально

Данные не хранятся в репозитории (170 МБ, внешний источник) — `datasets/`
в `.gitignore`. Скрипты здесь — только код, воспроизводящий стенд.

```bash
mkdir -p datasets/force2020
cd datasets/force2020
curl -L -o las.zip "https://zenodo.org/records/4351156/files/LAS_files_Force_2020_all_wells_train_test_blind_hidden_final.zip?download=1"
curl -L -o formations.xlsx "https://zenodo.org/records/4351156/files/NPD_Lithostratigraphy_member_formations_all_wells.xlsx?download=1"
unzip -q las.zip -d las
cd ../..
python3 bench/force2020/prepare-tops.py   # → datasets/force2020/{tops,heads}.csv
```

Затем прогон:

```bash
npx vitest run --config bench/force2020/vitest.config.ts --silent=false --reporter=verbose
```

## Что печатает стенд

Для каждого пространственного кластера скважин (см. `core/geom/cluster`,
тот же алгоритм, что режет ложную площадь на карте):

- сколько скважин и общих поверхностей в кластере;
- медиана / p75 / p90 ошибки разноса против разбивки NPD;
- доля предложений в пределах 20 м и 50 м;
- точность в разрезе по коэффициенту `r` — чтобы видеть, действительно ли
  уверенность предсказывает точность, или нет, как было на `private-data`;
- контроль: скважина сама на себя — обязана давать точное попадание
  (r = 1.000). Если нет — сломан не метод, а сам стенд.

## Что показал прогон

Полный разбор — [docs/product/correlation.md](../../docs/product/correlation.md).
Коротко: ошибка разноса монотонно растёт с расстоянием между скважинами (от
медианы ~70–120 м на 0–5 км до ~450–550 м за 60+ км), подсказка от соседней
уже привязанной поверхности стабильно снижает её вдвое на каждой дистанции, а
коэффициент уверенности лишь слабо предсказывает точность. FORCE 2020 —
региональные разведочные скважины, а не плотная сетка разработки: даже
ближайший бин (0–5 км) не эквивалентен кустовой скважине в реальном проекте,
так что вопрос «годится ли метод на скважинах одного месторождения» остаётся
открытым — нужен набор с шагом в сотни метров, не километры.
