# Инклинометрия: чтение русских выгрузок

Как GeoViewer читает замеры искривления и почему он читает их именно так.
Всё ниже проверено на двух реальных выгрузках — многоскважинной сводной таблице
и отчёте MWD по одной скважине; конкретные значения из них здесь не приводятся.

## Что ломает обычный парсер CSV

Ни одна из выгрузок не является CSV с одной строкой заголовка:

| Что встретилось | Почему это мешает |
| --- | --- |
| Заголовок размазан по 3–5 строкам | ни одна строка сама по себе не содержит имён колонок |
| В тех же строках сидит чужая легенда, сдвинутая на несколько колонок влево | текст заголовка перемешан с посторонним |
| Колонка скважины без заголовка | не за что зацепиться по имени |
| Строка с номерами колонок между шапкой и данными | читается как ещё одна станция |
| Три колонки азимута: истинный, магнитный, картографический | они различаются на склонение — до 21° |
| Десятичная запятая, разделитель `;`, кодировка cp1251 | всё вместе |
| `-` вместо числа | «замера нет», а не «ноль» |
| Единственная скважина названа только в преамбуле | в таблице её имени нет вообще |

## Как устроено чтение

**Шапка склеивается по столбцам.** Ячейки нескольких строк заголовка
соединяются сверху вниз внутри каждого столбца, и роли (глубина, зенит, азимут)
ищутся уже в склеенном тексте. Так вертикально разорванное «Ист.» + «Азимут»
снова становится одним именем.

**Глубина склейки подбирается сама.** Пробуются 1…8 строк, и берётся наименьшее
число, дающее максимум распознанных ролей при отсутствии конфликтов — когда одна
колонка претендует на две роли сразу. Это не украшение: сводной таблице нужно
пять строк, чтобы дотянуться до слова «Глубина», а в отчёте MWD семнадцатью
строками выше лежит «Азимут Вертикальной Секции» — и он садится ровно на ту же
колонку, что «Зенитный угол». Фиксированное окно ломает один из двух файлов.

**Азимут выбирается по приоритету:** истинный → картографический → магнитный →
без уточнения. Проверено на реальных данных: пересчёт траекторий по магнитному
азимуту расходится с собственными колонками отклонений выгрузки почти вдвое
сильнее, чем по истинному.

**Глубина по стволу отличается от «Ист. Глубина» и «Абс. Глубина».** Обе стоят
рядом с MD и обе содержат слово «Глубина»; первая — это TVD, вторая —
абсолютная отметка. Спутать их — значит превратить наклонную скважину в
вертикальную.

**Колонка скважины находится по структуре, если её не назвали.** Идентификатор
скважины занимает непрерывный блок строк, больше нигде не появляется, внутри
блока глубина растёт, а сам он не выглядит дробным числом. Ни одна колонка
измерений всем четырём условиям сразу не удовлетворяет.

**Скважина должна иметь хотя бы две станции.** Заодно это отсекает строку с
номерами колонок, которая иначе читается как скважина с единственным замером.

## Пропущенный азимут — самое важное решение

В сводной таблице азимут отсутствует у 2700 с лишним станций — там стоит `-`.
Все они принадлежат почти вертикальным участкам: зенит нигде не превышает 3.5°.

Соблазн — подставить какой-нибудь азимут (ноль или предыдущий известный) и
сохранить зенит. Это ошибка. Зенит 2°, проинтегрированный по трём километрам,
даёт около ста метров уверенного бокового смещения в выдуманную сторону.

Поэтому станция без записанного азимута **не смещается вбок вообще** — вместе с
азимутом обнуляется и зенит. Это единственный способ выразить «направление
неизвестно» в траектории. Ровно так же поступила и сама выгрузка: в её колонках
отклонений у таких скважин стоят нули.

Проверка на реальных данных, сверка с собственными колонками выгрузки:

| Обработка пропуска | Расхождение TVD | Расхождение отхода |
| --- | --- | --- |
| подставить азимут 0° | 0.77 м | **72.75 м** |
| обнулить зенит вместе с азимутом | 1.19 м | **2.12 м** |

Метр TVD в обмен на семьдесят метров плановых координат — размен очевидный.

Выше 5° зенита пропуск азимута считается уже не «здесь вертикально», а потерей
данных, и станция выбрасывается. Порог взят из данных: в реальном файле пропуски
не встречаются выше 3.5°.

## Что ещё сообщает импорт

- **Альтитуда точки отсчёта** — если она названа в преамбуле явно. Отметка земли
  или морского дна, стоящая рядом, намеренно не подхватывается.
- **Повторно замеренные скважины** — те, у которых глубина по ходу файла
  начинается заново. Это два прогона замеров, и какой из них главный, знает
  только недропользователь; склейка по глубине смешала бы две траектории.

## Проверка

Помимо синтетических тестов (`src/survey/inclinometry.test.ts`, форма реальных
файлов с вымышленными числами) разбор сверен с независимой величиной: выгрузка
сама содержит TVD и плановые отклонения, посчитанные буровым софтом. Пересчёт
траекторий из разобранных MD/зенита/азимута по минимальной кривизне сходится
по 56 скважинам с точностью **1.19 м по TVD и 2.12 м по отходу**.
